## Quick Start (Development)

### 1. Настроить PostgreSQL

Указать `DATABASE_URL` в `.env`.

PostgreSQL можно установить и запустить самостоятельно либо развернуть через Docker Compose:

```bash
docker compose up -d
```

### 2. Установить зависимости

```bash
npm i
```

### 3. Подготовить базу данных

Сгенерировать Prisma Client, применить миграции и выполнить seed:

```bash
npm run prepare:dev
```

### 4. Запустить сервер

```bash
npm run start
```

Apollo Sandbox доступен по адресу:

```text
http://localhost:3000/graphql
```

## Обоснование архитектурных решений

### DataLoader

Для вложенных коллекций используется DataLoader, чтобы избежать проблемы N+1 при запросе связанных сущностей для нескольких профилей.

### Many-to-many связь для навыков

Skill выделен в отдельную сущность и связан с Profile отношением many-to-many, поскольку навык является самостоятельной сущностью и потенциально может использоваться несколькими профилями.

### Отдельные типы сущностей для сервисов

Для сервисов определены отдельные типы входных данных. Они преимущественно дублируют GraphQL DTO, но это сделано намеренно, чтобы не связывать бизнес-логику с GraphQL-контрактом.

### Единая мутация для обновления профиля

`updateProfile` принимает изменения в виде патча и применяет изменения профиля и его связанных сущностей в рамках одной транзакции. Это позволяет реализовать сценарий единой кнопки «Сохранить» и гарантирует атомарность изменений.

Альтернативные варианты:

- **Отдельная мутация для каждой сущности** — изменения сохраняются отдельными запросами.
- **Draft / Published** — отдельные изменения сначала сохраняются в черновик, а затем публикуются целиком.

Выбор подхода зависит от требований UI и сценария редактирования.
